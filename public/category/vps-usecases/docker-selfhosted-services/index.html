    Docker 让一台 VPS 可以同时跑网盘、反向代理、代码仓库和监控面板，每个服务一条命令就能部署，也能随时删掉重来。很多人第一次接触自托管，就是从一台装了 Docker 的 VPS 开始的。

    这篇文章先讲清常见自托管服务各占多少内存和硬盘，再推荐四家适合跑 Docker 的商家：大内存独享核心、年付大硬盘、超大流量与按小时计费，每家都附上套餐表，方便按自己要跑的服务对照。

    Docker 自托管需要多大配置 #

    Docker 本身很轻，真正占资源的是你要跑的服务。同一台机器上的容器共享内存，所以选配置时要把计划部署的服务加起来算，再留出三成左右的余量，避免内存不足时容器被系统终止：

    常见服务用途内存占用参考硬盘需求
    Nginx Proxy Manager图形化反代与证书约 100~200MB很小
    Uptime Kuma网站与服务监控约 100MB很小
    Vaultwarden自建密码管理约 50MB很小
    Gitea自建代码仓库约 200~300MB视仓库大小
    Nextcloud + 数据库自建网盘与同步1GB 以上视文件多少

    上表是常见的经验范围，实际占用会随用户数和数据量变化。只跑反代、监控和密码管理这类轻量服务，1GB 内存就够；加上 Gitea 或 Nextcloud，建议直接选 4GB，后面再加服务也不用迁移。

    硬盘与流量 #

    网盘和相册类服务最吃硬盘，镜像文件本身也会占掉十几 GB，选机型时至少留出 2~3 倍于现有数据的空间。如果要在多台设备之间同步大文件，月流量和端口速度同样要留意，流量少的机型很快就会用完。

    机房与线路怎么选 #

    自托管服务的使用者通常只有你自己或几个朋友，对晚高峰的要求没有面向公众的网站那么高。选机房时主要看三点，再按服务类型决定要不要为线路多花钱：

    • 离自己近：网盘、密码管理用着更顺手；
    • 流量与硬盘：同步和备份不受限制；
    • 可快照迁移：折腾坏了能快速恢复。

    网盘、相册这类需要频繁传输文件的服务，延迟和带宽直接影响体验，可以优先考虑香港或优化线路机房。反代、监控、代码仓库对速度不敏感，美国普通线路的大内存、大硬盘机型更划算。

    另外，这类服务通常会暴露在公网上，部署后记得修改默认密码、开启防火墙，只开放需要的端口。后台面板尽量放在反代后面并启用 HTTPS，不要直接用 IP 加端口访问。

    长期运行固定服务 #

    如果你打算长期跑网盘、代码仓库、密码管理这类自用服务，稳定的资源、足够的硬盘空间和合适的价格，往往比开关机的灵活性更重要。按要跑的服务类型，可以这样选：

    常见问题解答 #

    跑 Docker 最少要多大内存？ #

    只跑几个轻量容器，1GB 内存加 1GB Swap 就能运行；要跑 Nextcloud、数据库或 Java 应用，建议 4GB 起。内存不足时，系统会优先终止占用最多的容器，服务会突然中断。

    什么样的 VPS 不能装 Docker？ #

    主要是 OpenVZ 与部分 LXC 虚拟化的机型，它们共享宿主机内核，无法正常运行 Docker。购买前在套餐页确认虚拟化类型为 KVM，就可以自己选择系统和内核，安装 Docker 没有限制。

    自建网盘放在美国机房会慢吗？ #

    上传下载大文件时会比较明显，美国普通线路晚高峰速度也不稳定。网盘以备份为主、不常同步的话影响不大；需要经常在国内设备间同步，香港或优化线路机房体验会好很多。

    Docker 面板用哪个比较省心？ #

    新手可以用 Portainer 或 1Panel 管理容器，它们都提供网页界面，能看到每个容器的状态和资源占用。熟悉命令行后，用 docker compose 文件管理服务更清晰，也方便迁移到新机器。

    迁移到新 VPS 要怎么做？ #

    把 docker compose 文件和数据卷目录打包，复制到新机器后重新启动即可，这也是用 Docker 自托管的一大好处。数据库类服务建议先导出数据，再在新机器上导入，避免文件复制时数据不一致。
