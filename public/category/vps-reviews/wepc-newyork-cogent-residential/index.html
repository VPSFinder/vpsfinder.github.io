    测试机型与测试环境 #

    本次测试的实例为 WePC 美国纽约 Cogent 家宽机型。以下配置均以系统内 lscpu、free、df 与 Bench.sh 的实际识别结果为准，而非套餐页上的标称值：

    • 处理器：Intel Xeon Gold 6138 @ 2.00GHz，分配 1 个 vCPU（KVM 虚拟化）
    • 内存与存储：467MB 可用内存，未配置 Swap，约 10GB 系统盘
    • 网络：独立 IPv4，归属 AS174 Cogent Communications，Bench.sh 定位在纽约
    • 测试系统：Ubuntu 22.04 LTS，内核 5.15，默认 cubic 拥塞控制，iperf3 部分对比了开启 BBR 前后的结果

    所有测试于 2026 年 8 月 11 日完成，IP、硬件与带宽检测在北京时间 15:20 至 15:35 进行，属于白天时段。本次 Backtrace 未输出结果，回程线路以单条去程路由追踪代替。

    IP 属性与流媒体解锁 #

    对住宅 IP 机器来说，这是最重要的一项，所以放在最前面。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 归属一级骨干运营商 Cogent 的 AS174，在 Maxmind 中的使用地与注册地均为美国，被判定为原生 IP。使用类型方面，IPinfo、ipregistry、ipapi 与 AbuseIPDB 四家一致判定为家宽，只有 IP2Location 判定为机房。

    风险评分出现了明显分歧。Scamalytics 与 AbuseIPDB 均为 0，ipapi 为 0.00% 极低风险，IP2Location 也只有 3 分；但 IPQS 给出了 94 分高风险，并将其判定为代理与 VPN。

    这意味着在以 IPQS 为风控依据的平台上，这个 IP 可能会触发额外验证。如果你的目标平台对风控极其敏感，建议开通后先用实际账号环境做小规模验证。

    邮件方面，本地 25 端口出站可用，能连通 Gmail、Outlook、Yahoo、Apple、QQ、163 与新浪邮箱，只有 GMX、Mail.com 与搜狐不通。423 个有效黑名单数据库中只有 2 个将其标记，没有任何一个将其列入黑名单。

    流媒体方面，Netflix、Disney+、Amazon Prime Video 与 TikTok 均可解锁美区，TVBAnywhere+ 与 Reddit 也可使用，Netflix 优选 CDN 位于纽约。不过 YouTube Premium 显示不可用，IPQuality 检测到的 YouTube 地区为中国。

    AI 服务方面，ChatGPT 与 Claude 可以正常访问，但 Google Gemini 不可用，Spotify 也无法注册。如果你的工作依赖 YouTube 或 Gemini，需要提前考虑这一点。

    国内三网延迟实测 #

    我们使用 Tcptest 调用 111 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    三网平均延迟分别为电信 251ms、联通 254ms、移动 266ms。国内最快的是天津电信 209ms 与河北承德联通 220ms，最慢的云南昆明联通达到 310ms，地图上西部与东北大片地区都在 250ms 以上。

    我们另外从服务器 Ping 上海电信骨干节点，4 次平均 223.7ms，抖动 3.4ms。这是美东机房的物理距离决定的，远程操作时会有明显的输入延迟感。

    持续丢包监测 #

    我们从 13 个国内节点对实例连续发起 100 次 Ping，覆盖三网运营商以及腾讯云、阿里云的机房出口：

    13 个节点中有 5 个为 0% 丢包，其余在 1% 到 3% 之间，最高为青岛阿里云 3%。对于美东普通线路来说，这个稳定性相当不错，各节点的标准差都在 4.3ms 到 5.0ms 之间。

    平均延迟方面，上海腾讯云 213ms、南京腾讯云 220ms 表现最好，成都 258ms，丽水移动最高为 276ms。

    去程路由追踪 #

    本次 Backtrace 没有输出结果，我们改为追踪上海电信到纽约方向的去程路由：

    数据包从上海电信 AS4812 出发，经电信 163 骨干网（AS4134）跨越太平洋，在旧金山接入 Cogent（AS174），此时延迟约 141ms，随后经盐湖城、丹佛一路东行，截图可见的最后一跳延迟约 170ms。

    整条链路在美国境内都走 Cogent 自家骨干网，截图可见的跳点中没有 CN2 节点。到达纽约还需要再横穿半个美国，这也是最终延迟在 220ms 以上的原因。

    带宽与下载速度 #

    带宽部分我们使用 Bench.sh 对全球多个测速节点进行了上传与下载测试：

    到美国与欧洲节点的上传都稳定在 189 Mbps 左右，下载在 133 到 197 Mbps 之间，与 200Mbps 的套餐端口基本一致。到蒙特利尔仅 15ms、巴黎与阿姆斯特丹约 73ms，美东与欧洲方向非常通畅。

    亚洲方向则明显变弱：香港上下行约 2 Mbps，新加坡上传 66 Mbps，东京与台北下载约 186 到 191 Mbps，苏州与宁波节点测试失败。Bench.sh 三轮磁盘写入平均 200.3 MB/s。

    我们还用一条 100Mbps 的电信家庭宽带，通过 iperf3 反向模式从服务器下载数据。默认 cubic 拥塞控制下平均只有 5 Mbps，开启 BBR 后提升到 21 Mbps 左右，开机后务必启用 BBR。

    常见问题解答 #

    WePC 纽约 Cogent 是真正的家宽 IP 吗？ #

    从数据库判定来看，IPinfo、ipregistry、ipapi 与 AbuseIPDB 都将其使用类型识别为家宽，只有 IP2Location 判定为机房。但 IPQS 将其判定为代理与 VPN，给出 94 分高风险，不同平台的判定可能不一致。

    WePC 纽约能看 YouTube 和用 Gemini 吗？ #

    本次实测 YouTube Premium 不可用，IPQuality 检测到的 YouTube 地区为中国，Google Gemini 也不可用。Netflix、Disney+、Prime Video、TikTok 以及 ChatGPT、Claude 均可正常使用。

    WePC 纽约到国内速度怎么样？ #

    三网平均延迟在 251ms 到 266ms，丢包率较低，但家宽 iperf3 下载默认只有 5 Mbps，开启 BBR 后约 21 Mbps。它适合做账号运营环境，不适合给国内用户提供下载或建站服务。

    WePC 能发外贸邮件吗？ #

    可以。25 端口出站可用，能连通 Gmail、Outlook、Yahoo、QQ 与 163 邮箱，423 个黑名单数据库中只有 2 个将其标记。测试中不通的只有 GMX、Mail.com 与搜狐。

    适用场景与选购建议 #

    综合六个维度的实测，WePC 纽约 Cogent 家宽的定位非常清晰：它提供了一个多数数据库认可的美东家宽环境，黑名单记录极少，但 IPQS 评分与部分服务的可用性需要使用者自行评估。

    适合的用户与业务：

    • 需要美东家宽 IP 运营海外社媒、外贸平台账号的用户
    • 需要 25 端口发送外贸邮件，且对黑名单记录有要求的业务
    • 需要访问 Netflix、Disney+、TikTok 与 ChatGPT、Claude 的个人用户

    不太适合的用户与业务：

    • 以 IPQS 评分作为主要风控依据的平台账号
    • 依赖 YouTube Premium 或 Google Gemini 的工作流
    • 面向国内访客的网站，或需要较大内存的应用部署

    WePC 支持工单按条款折算退款，月付门槛也不高。家宽 IP 的适配性高度依赖目标平台，最稳妥的做法是先开一个月，用真实账号环境验证之后再长期使用。
