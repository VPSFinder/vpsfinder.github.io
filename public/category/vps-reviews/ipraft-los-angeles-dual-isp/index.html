    IP 属性与流媒体解锁 #

    对住宅 IP 机器来说，这是最重要的一项，所以放在最前面。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 归属 AS214483 FiberPower LLC，在 Maxmind 中的使用地与注册地均为美国，被判定为原生 IP。使用类型方面，IPinfo、ipregistry 与 AbuseIPDB 一致判定为家宽，IP2Location 判定为商业。

    公司类型方面，IPinfo 与 ipregistry 判定为商业，IP2Location 判定为机房，说明数据库之间并非完全一致。对于大多数以“使用类型”为主要依据的风控系统来说，这个 IP 会被视为住宅网络。

    风险评分是这台机器最亮眼的部分：IP2Location、Scamalytics 与 AbuseIPDB 全部为 0 分，DB-IP 也是低风险。风险因子中，所有数据库对代理、VPN、服务器与滥用的判定都是“否”。

    邮件方面，本地 25 端口出站可用，能连通 Gmail、Outlook、Yahoo、Apple、QQ 与 163 等邮箱，GMX、Mail.com、搜狐与新浪不通。在 423 个有效黑名单数据库中，有 23 个将其标记，但没有任何一个将其正式列入黑名单。

    解锁表现非常完整。Netflix、Disney+、YouTube Premium、Amazon Prime Video、Dazn 与 TikTok 全部原生解锁美区，TVBAnywhere+ 与 Reddit 也可使用，只有 Spotify 无法注册。

    AI 服务同样全部可用，ChatGPT、Google Gemini 与 Claude 均能正常访问。配合干净的风险评分，这台机器很适合作为长期登录海外平台账号的固定环境。

    国内三网延迟实测 #

    我们使用 ITDOG 调用全国 287 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    全国平均延迟为 207ms，三网分别为电信 182ms、联通 188ms、移动 258ms。最快的是台北 134ms 与浙江嘉兴电信 138ms，最慢的是新疆伊犁移动 338ms，移动整体明显落后于电信与联通。

    我们另外从服务器 Ping 上海电信骨干节点，4 次平均 148.2ms，抖动 1.5ms。对于远程登录后台、操作跨境电商店铺这类场景，电信与联通用户的体验尚可，移动用户会感觉明显延迟。

    持续丢包监测 #

    我们在 19:27 至 19:34 期间，从 13 个国内节点对实例连续发起 100 次 Ping。

    13 个节点中只有广州腾讯云、江苏联通与丽水联通为 0%，江苏电信丢包最高为 10%，江苏移动与丽水移动为 8%，丽水电信 7%，其余云厂商节点在 1% 到 6% 之间。

    平均延迟集中在 152ms 到 193ms，江苏移动与丽水移动则在 232ms 到 237ms，标准差高达 43ms，延迟曲线波动明显。移动用户在傍晚时段远程操作，可能会遇到卡顿。

    去程路由追踪 #

    本次 Backtrace 没有输出结果，我们改为追踪上海电信到洛杉矶方向的去程路由：

    数据包从上海电信 AS4812 出发，经电信 163 骨干网（AS4134）跨越太平洋，随后转入 Hurricane Electric（AS6939），途经圣何塞、洛杉矶与费利蒙的 HE 节点，截图可见的最后一跳延迟约 150ms。
