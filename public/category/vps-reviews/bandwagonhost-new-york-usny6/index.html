    这次我们在 USNY_6 开通了一台 Basic VPS 2核1G 实例，从延迟、丢包、路由、硬件、带宽和 IP 属性六个维度做了完整测试。美东机房离国内远，下面会把国内访问与欧美访问的表现分开来看。

    测试机型与测试环境 #

    本次测试的实例为搬瓦工纽约 USNY_6 机房的 Basic VPS 2核1G 款，这款年付 49.99 美元的入门套餐目前已经下架。以下配置均以系统内命令与 Bench.sh 的实际识别结果为准：

    • 处理器：AMD EPYC-Genoa，分配 2 个 vCPU
    • 内存与存储：1GB 内存与 545MB Swap，20GB 系统盘
    • 网络：独立 IPv4，归属 AS25820 IT7 Networks
    • 测试系统：Ubuntu 24.04 LTS，内核 6.8，已开启 BBR

    IT7 Networks 是搬瓦工背后的网络运营方，USNY_6 的 IP 显示位于纽约市，注册地为加拿大。系统内没有检测到可用的 IPv6，延迟与丢包部分在北京时间晚上 8 点前后采集，正好是国内晚高峰。

    国内三网延迟实测 #

    美东机房到国内要横跨整个北美，再走太平洋海缆，物理距离决定了延迟不可能低于美西机房。我们使用 Tcptest 调用全国 97 个监测节点，在晚上 8 点对这台实例发起了延迟测试：

    全国平均延迟为 229ms，三网分别为电信 233ms、联通 242ms、移动 265ms。最快的国内节点是上海电信 207ms 与南昌联通 218ms，最慢的是拉萨移动 298ms，移动整体比电信联通慢 20~30ms。

    按地区看，华东平均 235ms、华北 238ms、华南 242ms，西北与西南则在 250ms 左右，港澳台节点平均 212ms。对比美西普通线路晚高峰 220ms 左右的水平，纽约只多出十几毫秒，绕路情况并不严重。

    持续丢包监测 #

    延迟之外，丢包率更能反映晚高峰的实际可用性。我们从国内 13 个节点对实例连续发起 100 次 Ping，覆盖三网运营商以及腾讯云、阿里云的机房出口：

    运营商节点的表现相对稳定，江苏联通与丽水联通为 0%，丽水移动 3%，江苏电信 5%，丽水电信 7%，只有江苏移动达到 13%。云厂商出口波动更大，广州腾讯云 20%，南京腾讯云与青岛阿里云均为 12%。

    全部节点的平均丢包率在 7.76% 以内，晚高峰浏览网页、SSH 管理服务器依旧能保证不错的体验。如果业务对国内晚高峰要求更高，更好的做法是选择搬瓦工的 CN2 GIA 线路机房，而不是在纽约机房上硬扛。

    回程路由追踪 #

    我们从上海电信对实例做了路由追踪，可以清楚看到流量从国内出去后的走向：

    流量从上海电信 AS4812 进入电信 163 骨干网 AS4134，出国后先在美国加州圣何塞接入 HE 骨干，再横跨北美到纽约，最后进入 IT7 自己的 AS25820 网络。全程没有经过 CN2 节点，属于普通线路。

    经过美西再转纽约的路径解释了 230ms 左右的延迟，太平洋段约 150ms，横跨北美又增加约 50ms。从实例直接 Ping 上海电信 DNS 为 200ms、0 丢包，与路由追踪的结果一致。

    EPYC-Genoa 是 AMD 第四代 EPYC 服务器处理器，单核 Sysbench 得分 3,254 events/s，是 RackNerd 圣何塞 E5 老平台的 3.6 倍。双核得分 6,499，几乎是单核的两倍，说明两个核心都能稳定跑满，没有被邻居明显挤占。

    同样是 EPYC-Genoa， Evoxt 洛杉矶 的单核为 5,645，搬瓦工这台的频率设定更保守。对建站、反向代理和日常开发来说，3,000 以上的单核得分已经足够，编译中等规模的项目也不会明显卡顿。

    磁盘方面，FIO 单队列 4K 随机混合读写各约 5,600 IOPS，换用 libaio 引擎测试时 4K 随机写达到 87.3k IOPS、随机读约 6,016 IOPS。Bench.sh 三轮写入平均 875.7 MB/s，承载数据库较多的 WordPress 站点也没有压力。

    带宽与下载速度 #

    带宽部分我们先用 Speedtest 连接纽约本地节点，再用 Bench.sh 测试全球多个节点的上传与下载：

    纽约本地 Speedtest 下载 8,667 Mbps、上传 6,973 Mbps，延迟 0.93ms、0 丢包。欧洲方向同样出色，阿姆斯特丹下载 9,249 Mbps、巴黎 7,859 Mbps，蒙特利尔上传 6,292 Mbps，欧美之间传输大文件非常快。

    亚洲方向则明显收窄：苏州节点下载 4,130 Mbps、上传 396 Mbps，台北下载 5,631 Mbps，东京下载约 906 Mbps，香港节点上下行都只有 3~4 Mbps。洛杉矶、宁波与新加坡节点本次测试未能连通。

    国内家庭宽带直连的体验也需要说明：用 100Mbps 电信家宽通过 iperf3 测试下载，没开 BBR 时不到 1Mbps，开启 BBR 后能到 10Mbps 左右。新开的机器建议第一时间确认 BBR 已经开启。

    IP 属性与流媒体解锁 #

    最后我们检测了这台实例的 IP 质量与常见服务的解锁情况。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 被识别为纽约的广播 IP，各大数据库的使用类型均标记为机房。Scamalytics 3 分、AbuseIPDB 0 分、ipapi 0.29%，均为低风险；但 IP2Location 给出 99 分高风险，IPQS 给出 75 分可疑，部分数据库还标记为 VPN。

    邮件方面，本地 25 端口出站可用，能连通 Gmail、Outlook、Yahoo、Apple、QQ、163 与新浪等邮箱，只有 GMX 与 Mail.com 不通。在 439 个有效黑名单数据库中有 50 个标记，但黑名单收录为 0，发信条件在美国机房里算好的。

    流媒体方面，Netflix、Disney+、YouTube Premium、Amazon Prime Video、TikTok 与 Dazn 全部解锁美区，并且都是原生解锁，YouTube CDN 就在纽约本地。只有 Spotify 注册不可用，Bing 地区标记为有风险。

    AI 服务同样全部可用，ChatGPT、Google Gemini 与 Claude 都能正常访问，Google 搜索也没有弹出验证码。对需要调用 AI 接口或者观看美区流媒体的用户来说，这台机器几乎没有短板。

    常见问题解答 #

    搬瓦工纽约机房是 CN2 线路吗？ #

    不是。上海电信的路由追踪显示，回国流量走电信 163 骨干，经美西 HE 骨干到纽约，全程没有 CN2 节点。晚高峰全国平均延迟 229ms，需要 CN2 GIA 线路时，应选择搬瓦工的 E-Commerce 系列。

    纽约机房适合做国内访问的网站吗？ #

    不太适合作为首选。晚高峰三网延迟在 233ms 到 265ms 之间，部分节点丢包超过 10%，国内访客打开网页会明显偏慢。如果一定要用，建议搭配 CDN；访客在欧美的外贸站则非常合适。

    搬瓦工纽约能看 Netflix 和用 ChatGPT 吗？ #

    可以。本次实测 Netflix、Disney+、YouTube Premium、Prime Video 与 TikTok 全部原生解锁美区，ChatGPT、Gemini 与 Claude 均可正常访问，Google 搜索也没有出现验证码。

    搬瓦工纽约适合自建邮局吗？ #

    条件不错。25 端口出站可用，能连通 Gmail、Outlook、QQ 与 163 等主流邮箱，黑名单收录为 0。不过 IP2Location 与 IPQS 的风险评分偏高，自建邮局前仍建议配置好 rDNS、SPF 与 DKIM。

    测试的这款套餐还能买吗？ #

    不能。本次测试的 2核1G 年付款已经下架，目前 Basic VPS 的最低档为 3核2G、40GB 硬盘，半年付 52.99 美元，同样可以选择纽约机房，配置比测试机更宽裕。

    适用场景与选购建议 #

    综合六个维度的实测，搬瓦工纽约 USNY_6 的定位很清晰：新硬件带来了扎实的算力和磁盘性能，欧美方向带宽充足、解锁全面，但回国只是普通线路，不能按 CN2 GIA 机房的标准去要求国内访问速度。

    适合的用户与业务：

    • 访客在北美、欧洲的外贸独立站与企业官网

    不太适合的用户与业务：

    • 主要访客在国内、对晚高峰速度敏感的网站
    • 需要从香港、东南亚频繁拉取数据的业务
    • 对 IP 风控评分要求严格的平台账号运营
