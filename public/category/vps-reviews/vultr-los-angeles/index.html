    测试机型与测试环境 #

    本次测试的实例为 Vultr 洛杉矶机房的 1核1G 机型。以下配置均以系统内 lscpu、free 与 df 命令的实际识别结果为准，而非套餐页上的标称值：

    • 处理器：Intel Core Processor（Broadwell）@ 2.40GHz，分配 1 个 vCPU
    • 内存与存储：951MB 可用内存，另有 2.3GB Swap，约 25GB 系统盘
    • 网络：独立 IPv4，归属 AS20473 The Constant Company（Vultr）
    • 测试系统：Ubuntu 22.04.5 LTS，内核 5.15，已开启 BBR 拥塞控制

    所有测试于 2026 年 1 月 13 日完成，延迟与丢包在北京时间 13:50 至 14:05 采集，属于白天时段。本次 Backtrace 未输出结果，回程线路以单条去程路由追踪代替。

    国内三网延迟实测 #

    我们使用 ITDOG 调用全国 159 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    全国平均延迟为 195ms，三网分别为电信 182ms、联通 192ms、移动 214ms。最快的是江西南昌电信 146ms 与南昌联通 156ms，华东地区平均 187ms，新疆、西藏等西部地区则超过 200ms。

    这是美西普通线路的常见水平，比走 CN2 的洛杉矶机器慢 30ms 到 50ms。从服务器 Ping 百度香港节点约 178ms，也印证了它与亚洲方向之间并没有特别优化。

    持续丢包监测 #

    我们在 13:51 至 13:58 期间，从 14 个国内节点对实例连续发起 100 次 Ping。

    丢包是这台机器最明显的短板。只有江苏联通与丽水联通为 0%，成都与贵阳为 1%，其余节点多在 7% 到 12% 之间，广州、南京腾讯云与江苏移动都达到了 12%。

    平均延迟集中在 148ms 到 200ms，但重庆腾讯云、江苏移动、丽水电信与上海阿里云都出现过 1 秒以上的最差值，标准差高达 47ms 到 176ms。白天尚且如此，晚高峰只会更差。

    去程路由追踪 #

    本次 Backtrace 没有输出结果，我们改为追踪上海电信到洛杉矶方向的去程路由：

    数据包从上海电信 AS4812 出发，经电信 163 骨干网（AS4134）抵达美国圣何塞，此时延迟已在 190ms 到 200ms，随后转入 NTT（AS2914）网络到达洛杉矶。

    截图可见的跳点中没有任何 CN2 节点，属于典型的普通国际线路。

    带宽与下载速度 #

    带宽是 Vultr 最强的一项。我们使用 Bench.sh 对全球多个测速节点进行了上传与下载测试：

    本地测速节点上传 6,365 Mbps、下载 4,019 Mbps，远超常见的 1Gbps 端口。远程方向中，上海节点下载 3,120 Mbps、上传 1,121 Mbps，东京与巴黎也都在 1.6 Gbps 以上。

    亚洲方向同样存在短板：香港节点上传仅 3.9 Mbps、下载 4.8 Mbps，新加坡上传只有 11.6 Mbps，与亚洲服务器频繁交互的业务需要提前评估。Bench.sh 三轮磁盘写入平均 466 MB/s。

    我们还用一条 100Mbps 的电信家庭宽带，通过 iperf3 反向模式从服务器下载数据。10 秒内平均速度 46.6 Mbps，每秒速率在 2.6 到 76 Mbps 之间波动，重传多达 3,210 次，与前面的丢包数据相互印证。

    IP 属性与流媒体解锁 #

    最后我们检测了这台实例的 IP 质量与常见服务解锁情况。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 在 Maxmind 中被识别为美国洛杉矶的原生 IP，各大数据库的使用类型均标记为机房。IP2Location 与 AbuseIPDB 为低风险，但 Scamalytics 给出 38 分中风险，ipapi 标记为高风险。

    IPQS 给出 75 分可疑评级，并将其判定为代理与 VPN，Scamalytics 也标记了 VPN。这在大厂云 IP 中很常见，对需要注册风控严格平台的用户来说要特别注意。

    邮件方面，本地 25 端口出站被阻断，无法直接自建邮局发信。在 439 个有效黑名单数据库中，有 34 个将其标记，但没有任何一个将其正式列入黑名单。

    流媒体方面，Netflix、YouTube Premium 与 TikTok 均可解锁美区，TVBAnywhere+ 也可解锁，Netflix 与 YouTube 的 CDN 均位于洛杉矶。Disney+ 与 Dazn 显示 IP 被封禁，Prime Video 两个脚本结果不一致。

    AI 服务方面，ChatGPT 与 Claude 可以正常访问，Google Gemini 则显示不可用。如果你的工作流依赖 Gemini，需要换一个 IP 或机房再测。

    常见问题解答 #

    Vultr 洛杉矶到国内速度怎么样？ #

    白天三网平均 182ms 到 214ms，走电信 163 与 NTT 的普通线路，多数节点白天就有 7% 到 12% 的丢包。面向国内访客建站不推荐直接使用，至少需要搭配 CDN。

    Vultr 的带宽真的有几 Gbps 吗？ #

    Bench.sh 实测本地节点下载 4 Gbps、上传 6.3 Gbps，上海节点下载也达到 3.1 Gbps，国际带宽非常充裕。但国内家宽实际下载受线路质量限制，本次只有 46.6 Mbps 左右。

    Vultr 洛杉矶 IP 干净吗，能用 ChatGPT 吗？ #

    ChatGPT 与 Claude 可以正常使用，Netflix 能解锁美区。但 IPQS 将其判定为代理与 VPN，给出 75 分可疑评级，Gemini 也不可用，对 IP 纯净度有要求的业务需要谨慎。

    IP 不好用可以换吗？ #

    可以。Vultr 按小时计费，销毁实例后重新开通就会分配新的 IP。

    适用场景与选购建议 #

    综合六个维度的实测，Vultr 洛杉矶的定位非常清晰：它的强项是灵活计费与充裕的国际带宽，回国线路和 IP 纯净度都只是普通水平，不适合直接承载面向国内的业务。

    适合的用户与业务：

    • 需要临时开发测试环境、CI 构建机或多地区部署的开发者
    • 面向海外访客的网站、API 服务与需要大带宽的国际数据传输
    • 需要频繁更换 IP 或短时间使用的测试场景

    不太适合的用户与业务：

    • 主要访客在国内、对延迟与丢包敏感的网站
    • 对 IP 风控评分要求严格的平台账号运营
    • 需要 25 端口自建邮局，或依赖 Google Gemini 的场景

    Vultr 不提供退款，但按小时计费本身就是最好的试错机制：开一台实例跑几个小时的测试只需要几美分，不满意直接销毁，几乎没有任何决策成本。
