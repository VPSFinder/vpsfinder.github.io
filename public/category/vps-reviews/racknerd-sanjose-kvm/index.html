    测试机型与测试环境 #

    本次测试的实例为 RackNerd 圣何塞机房的 1核1G 年付特价机。以下配置均以系统内 lscpu、free 与 df 命令的实际识别结果为准，而非套餐页上的标称值：

    • 处理器：Intel Xeon E5-2680 v2 @ 2.80GHz，分配 1 个 vCPU（KVM 虚拟化）
    • 内存与存储：961MB 可用内存，另有 1GB Swap，24GB 系统盘
    • 网络：独立 IPv4，归属 AS36352（ColoCrossing 网络），未分配 IPv6
    • 测试系统：Ubuntu 24.04 LTS，内核 6.8，默认 cubic 拥塞控制，未开启 BBR

    所有测试于 2026 年 1 月 3 日完成，延迟与丢包部分在北京时间上午 10:30 前后采集，属于白天时段。晚高峰的表现会比本文数据更差，下文会单独说明。

    国内三网延迟实测 #

    美西机房到国内的物理延迟本身就在 130ms 以上，关键看线路是否绕路。我们使用 ITDOG 调用全国 159 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    全国平均延迟为 189ms，三网分别为电信 162ms、联通 187ms、移动 226ms。最快的是上海联通 132ms 与安徽滁州电信 133ms，最慢的是新疆乌鲁木齐移动 277ms，移动整体明显落后。

    以上是白天数据。根据我们的长期观察，到了晚间高峰时段，全国平均延迟会上升到 220ms 左右，网页首屏加载会比白天慢一截，这是美西普通线路的共性。

    持续丢包监测 #

    延迟之外，丢包率更能反映线路的实际可用性。我们从 14 个国内节点对实例连续发起 100 次 Ping，覆盖三网运营商以及腾讯云、阿里云、华为云的机房出口：

    丢包表现两极分化。江苏移动、江苏联通、丽水电信与青岛阿里云为 0%，大部分云厂商节点在 1% 到 5% 之间，但丽水联通高达 37%，丽水移动也有 12%。

    平均延迟方面，云厂商与电信节点集中在 148ms 到 175ms，江苏联通 209ms，江苏与丽水的移动则在 230ms 到 247ms。即便在白天，部分运营商线路的波动已经比较明显。

    三网回程路由追踪 #

    我们使用 Backtrace 对北京、上海、广州、成都四地三网进行了回程检测，结果非常整齐：

    四地电信全部走电信 163，联通全部走联通 4837，移动全部走移动 CMI，均为直连国内骨干的普通线路，没有出现 CN2 GIA、9929 这类精品网。

    这也解释了上面的延迟与丢包数据：普通线路在国际出口拥堵时没有优先保障，晚高峰体验会明显下降。面向国内访客的网站，建议搭配 CDN 使用。

    E5-2680 v2 是一颗 2013 年发布的服务器处理器，单核 Sysbench 得分 896 events/s，跑博客、反向代理或定时脚本足够，但编译大型项目或运行高并发应用会明显吃力。

    解读磁盘数据前需要先说明测试方法：FIO 采用 psync 引擎、单队列深度运行，4K 随机混合读写未绕过系统缓存；1M 顺序读写虽然加了 direct 参数，但仅用 0.37 秒完成，也可能命中了宿主机缓存。

    在这一前提下，4K 随机读写各约 3,160 IOPS，Bench.sh 三轮写入平均 575 MB/s，对一台年付特价机来说存储表现相当扎实，承载 WordPress 这类中小型数据库站点没有压力。

    带宽与下载速度 #

    带宽部分我们使用 Bench.sh 对全球多个测速节点进行了上传与下载测试：

    本地测速节点上传 847 Mbps、下载 877 Mbps，基本跑满 1Gbps 端口。远程方向中，东京下载 817 Mbps、巴黎 840 Mbps，上海节点上传 400 Mbps、下载 468 Mbps，北美与欧洲方向带宽都很充足。

    亚洲方向则表现参差：新加坡下载 580 Mbps，但上传只有 71 Mbps；香港节点上传仅 4.7 Mbps、下载 2.9 Mbps，几乎不可用。如果业务需要与香港服务器频繁交互，需要提前评估。

    IP 属性与流媒体解锁 #

    最后我们检测了这台实例的 IP 质量与常见服务解锁情况。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 在 Maxmind 中被识别为美国加州圣克拉拉的原生 IP，各大数据库的使用类型均标记为机房。IP2Location 仅 3 分、AbuseIPDB 为 0，但 Scamalytics 给出 47 分中风险，ipapi 也标记为高风险。

    邮件方面，本地 25 端口出站可用，能连通 Gmail、Outlook、Yahoo、QQ 与 163 等邮箱，只有 GMX、Mail.com 与搜狐不通。但在 439 个有效黑名单数据库中，有 23 个已标记、5 个列入黑名单，自建邮局的送达率可能受到影响。

    流媒体方面，Netflix、YouTube Premium、Amazon Prime Video 与 TikTok 均可解锁美区，TVBAnywhere+ 也可解锁，Netflix 优选 CDN 位于圣何塞。不过 Disney+ 与 Dazn 均显示 IP 被封禁，Spotify 和 Reddit 也无法使用。

    AI 服务是这台机器的亮点，ChatGPT、Google Gemini 与 Claude 均可正常访问。对于需要调用 AI 接口的脚本或开发测试环境来说，这一点非常实用。

    常见问题解答 #

    RackNerd 圣何塞是 CN2 线路吗？ #

    不是。Backtrace 检测显示三网回程分别走电信 163、联通 4837 与移动 CMI，都是普通线路。白天三网平均延迟 162ms 到 226ms，晚高峰全国平均会上升到 220ms 左右。

    年付特价机能用来建站吗？ #

    可以，但要看访客来源。面向海外访客的外贸站、博客完全没问题；面向国内访客的网站，建议搭配 Cloudflare 等 CDN 使用，否则晚高峰的首屏加载会比较慢。

    RackNerd 能用 ChatGPT 和 Claude 吗？ #

    可以。本次实测 ChatGPT、Google Gemini 与 Claude 均可正常访问，Netflix、YouTube Premium 与 Prime Video 也能解锁美区，但 Disney+ 与 Dazn 均显示 IP 被封禁。

    RackNerd 圣何塞适合自建邮局吗？ #

    不太推荐。25 端口虽然出站可用，但 IP 在 5 个黑名单数据库中被收录，Scamalytics 也给出中风险评分，发信进垃圾箱的概率较高，发送通知邮件建议使用第三方 SMTP 服务。

    适用场景与选购建议 #

    综合六个维度的实测，RackNerd 圣何塞特价机的定位非常清晰：它用极低的年付价格提供了够用的硬件与充足的国际带宽，但国内网络只是普通线路水平，不能按精品线路的标准去要求。

    适合的用户与业务：

    • 预算有限，需要一台长期在线的机器学习 Linux、跑定时脚本或做备用机
    • 面向海外访客的外贸站、个人博客，或搭配 CDN 使用的轻量网站
    • 需要访问 ChatGPT、Gemini、Claude 等 AI 服务的开发与自动化测试环境

    不太适合的用户与业务：

    • 主要访客在国内、对晚高峰速度和丢包敏感的业务，尤其是移动用户占比高的网站
    • 需要自建邮局，或对 IP 风控评分要求严格的平台账号运营
    • 需要较强 CPU 算力的编译、转码等计算密集型任务

    RackNerd 的特价机支持支付宝付款，年付总价只有二十多美元，试错成本很低。如果你对线路没有特别要求，买一台用来练手或当备用机，几乎不会后悔。
