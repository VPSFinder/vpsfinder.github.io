    测试机型与测试环境 #

    本次测试的实例为丽萨主机美国洛杉矶 4837 双 ISP 系列的 1核1G 机型。以下配置均以系统内 lscpu、free 与 df 命令的实际识别结果为准，而非套餐页上的标称值：

    • 处理器：Intel Xeon E5-2680 v4 @ 2.40GHz，分配 1 个 vCPU（KVM 虚拟化）
    • 内存与存储：961MB 可用内存，未配置 Swap，约 20GB 系统盘（ext4）
    • 网络：独立 IPv4，归属 AS174 Cogent Communications，未分配 IPv6
    • 测试系统：Ubuntu 24.04.1 LTS，内核 6.8，默认 cubic 拥塞控制，未开启 BBR

    所有测试于 2026 年 6 月 15 日完成，延迟、丢包与路由部分在北京时间 18:40 前后采集，属于傍晚时段，尚未进入 20:00 之后的晚高峰。

    IP 属性与流媒体解锁 #

    对住宅 IP 机器来说，这是最重要的一项，所以放在最前面。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 归属 AS174 Cogent，在 Maxmind 中的使用地与注册地均为美国加州洛杉矶，被判定为原生 IP。使用类型方面，IPinfo、ipregistry、ipapi 与 AbuseIPDB 四个数据库一致判定为家宽，只有 IP2Location 判定为机房。

    风险评分整体很低：IP2Location 3 分、Scamalytics 5 分、ipapi 0.23%、AbuseIPDB 0 分，DB-IP 也是低风险。唯一的例外是 IPQS 给出了 75 分的可疑评级，原因是它将该 IP 判定为代理与 VPN。

    风险因子表中，只有 IP2Location 与 Scamalytics 标记了“服务器”，其余数据库对代理、VPN、服务器与滥用的判定都是“否”。对于以使用类型为主要依据的风控系统，这个 IP 会被视为住宅网络。

    邮件方面，本地 25 端口出站被阻断，远端 25 端口也不可达，无法直接自建邮局发信。在 439 个有效黑名单数据库中，有 31 个将其标记，2 个将其列入黑名单，做邮件业务需要另选方案。

    我们还用国内常用的 ping0.cc 做了一次交叉检测：

    ping0.cc 同样判定为原生 IP，风控值 11%，评级为“极度纯净”，共享人数 1 到 10 人。不过它把 IP 类型标为 IDC 机房，适用场景中 TikTok、跨境电商与社媒运营为三星“可以尝试”，AI 应用为四星“适合”。

    解锁表现非常完整。Netflix、Disney+、YouTube Premium、Prime Video 与 Dazn 全部解锁美区，IPQuality 中 TikTok 同样判定为原生解锁，Netflix 与 YouTube 的 CDN 均位于洛杉矶，只有 Spotify 无法注册。

    AI 服务方面，ChatGPT、Google Gemini 与 Claude 均能正常访问，Google 搜索也没有触发验证码。配合偏低的风险评分，它很适合作为长期登录海外平台账号的固定环境。

    国内三网延迟实测 #

    我们使用 Tcptest 调用全国 109 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    全国平均延迟为 187ms，三网分别为电信 191ms、联通 191ms、移动 211ms。最快的是天津联通 161ms 与浙江绍兴电信 165ms，华北地区平均 184ms，西南地区最高为 209ms，云南昆明联通 251ms 是最慢的节点。

    这是洛杉矶普通线路的常见水平，比走 CN2 的洛杉矶机器慢 30ms 左右。我们从服务器 Ping 上海电信骨干节点，4 次平均 164ms、无丢包，Ping 百度香港节点约 158ms，与延迟地图基本一致。

    持续丢包监测 #

    单次 Ping 只能说明瞬时状态，我们又用 ITDOG 从 140 余个国内三网节点对实例各发起 100 次 Ping。原图很长，下面截取电信节点的前半部分：

    142 个国内节点中，约 128 个丢包率为 0%，其余大多在 1% 到 4% 之间，对一条普通线路来说相当出色。平均延迟方面，电信多在 157ms 到 224ms，联通 171ms 到 228ms，移动 184ms 到 233ms。

    例外也需要说明：江西九江电信与河北石家庄电信两个节点 100% 超时，福建厦门联通丢包 56%，安徽芜湖电信 15%。同省的其他节点都是 0%，因此更像是个别监测点的问题，而非线路整体缺陷。

    带宽与下载速度 #

    带宽部分我们同时使用了 Bench.sh 全球节点测速与家庭宽带 iperf3 实测：

    Bench.sh 三轮磁盘写入平均 309 MB/s。网络测速中，实例上传到洛杉矶本地节点高达 8.8 Gbps，到苏州约 635 Mbps，到东京约 1 Gbps；下载方向则全部稳定在 280 到 308 Mbps，与套餐标称的 300Mbps 端口一致。

    亚洲方向也有短板：香港节点上传仅 4.77 Mbps、下载 3.1 Mbps，宁波节点上传只有 1.28 Mbps，与亚洲服务器频繁交互的业务需要提前评估。

    我们还用一条 100Mbps 的电信家庭宽带，通过 iperf3 反向模式从服务器下载数据。10 秒内平均速度 16.9 Mbps，前 3 秒缓慢爬升，之后稳定在 20 到 26 Mbps，重传 1,421 次。默认 cubic 拥塞控制下单线程回国下载偏慢，建议开启 BBR。

    常见问题解答 #

    丽萨主机 4837 是真正的住宅 IP 吗？ #

    本次实测中，IPinfo、ipregistry、ipapi 与 AbuseIPDB 四个数据库判定为家宽，只有 IP2Location 判定为机房，ping0.cc 也标为 IDC 机房。它更接近“双 ISP 原生 IP”，而非真实家庭宽带，核心主账号可考虑商家的真实家宽 VDS。

    适合 TikTok 和跨境电商运营吗？ #

    适合大多数场景。TikTok 原生解锁美区，Scamalytics 仅 5 分、多数数据库无代理与 VPN 标记。需要注意 IPQS 给出 75 分可疑评级，对 IPQS 敏感的平台建议先小规模测试。

    丽萨主机 4837 回国速度怎么样？ #

    三网回程都走联通 4837 普通线路，全国平均延迟 187ms。傍晚 140 余个节点的持续 Ping 绝大多数为 0 丢包，远程登录与后台操作比较流畅，但单线程下载只有约 20 Mbps。

    能用来自建邮局发邮件吗？ #

    不能。本次实测本地 25 端口出站被阻断，远端 25 端口也不可达，且有 2 个黑名单数据库收录了该 IP，邮件业务建议使用第三方发信服务。

    适用场景与选购建议 #

    综合六个维度的实测，丽萨主机洛杉矶 4837 双 ISP 的定位非常清晰：它的价值在于干净的 IP 属性、完整的解锁和意外稳定的回国丢包表现，而不是线路速度或硬件性能。

    适合的用户与业务：

    • TikTok 运营、跨境电商店铺与海外社媒矩阵，需要美国固定出口 IP 的账号环境
    • 需要稳定访问 ChatGPT、Gemini、Claude 等 AI 服务，或观看美区流媒体的用户
    • 每天从国内远程登录、对丢包敏感但不追求极低延迟的后台管理场景

    不太适合的用户与业务：

    • 面向国内访客、对延迟和下载速度要求高的网站
    • 需要 25 端口自建邮局，或对 IPQS 评分有硬性要求的平台账号
    • 需要高单核性能的编译、数据库与高并发建站业务
