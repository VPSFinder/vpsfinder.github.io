    测试机型与测试环境 #

    本次测试的实例为 JustHost 洛杉矶机房的 1核1G 机型。以下配置均以系统内 lscpu、free、df 与 Bench.sh 的实际识别结果为准，而非套餐页上的标称值：

    • 处理器：Intel Xeon E5-2697 v4 @ 2.30GHz，分配 1 个 vCPU（KVM 虚拟化）
    • 内存与存储：961MB 可用内存，未配置 Swap，20GB 系统盘
    • 网络：独立 IPv4 与 IPv6 双栈，归属 AS26383 Baxet Group Inc.
    • 测试系统：Ubuntu 24.04.4 LTS，内核 6.8，默认 cubic 拥塞控制，未开启 BBR

    所有测试于 2026 年 5 月 8 日完成，延迟、丢包与 IP 检测在北京时间上午 10:00 至 10:20 采集，属于白天时段。本次 Backtrace 未输出结果，回程线路以单条去程路由追踪代替。

    国内三网延迟实测 #

    我们使用 ITDOG 调用全国 160 个监测节点，对这台实例发起了三网 ICMP 延迟测试：

    全国平均延迟为 193ms，三网分别为电信 179ms、联通 203ms、移动 200ms。最快的是江苏南通电信 152ms，北京电信 156ms，港澳台平均 149ms，最慢的四川成都联通为 242ms。

    各大区平均延迟都在 186ms 到 204ms 之间，地区差异不大。我们另外从服务器 Ping 上海电信骨干节点，4 次平均 156.4ms，抖动 3.3ms，属于美西普通线路的正常水平。

    持续丢包监测 #

    我们在 10:02 至 10:05 期间，从 13 个国内节点对实例连续发起 101 次 Ping。

    13 个节点中有 7 个为 0% 丢包，南京腾讯云、丽水移动为 1%，江苏电信与丽水电信为 2%。丢包较多的是广州腾讯云 5% 与上海阿里云 6.9%，整体在普通线路中属于中上水平。

    平均延迟方面，上海腾讯云 150ms、丽水电信 156ms 表现最好，江苏联通 216ms、丽水联通 253ms 则明显偏高。大部分节点的标准差在 4.4ms 以内，延迟曲线比较平稳。

    去程路由追踪 #

    本次 Backtrace 没有输出结果，我们改为追踪上海电信到洛杉矶方向的去程路由：

    数据包从上海电信 AS4812 出发，经电信 163 骨干网（AS4134）直接抵达洛杉矶，此时延迟约 150ms，随后转入 NTT（AS2914），最终进入 Baxet 的 AS26383 网络，到达延迟约 178ms。

    截图可见的跳点中没有绕道第三地，但也没有任何 CN2 节点，属于普通国际线路。面向国内访客的网站，建议搭配 CDN 使用，晚高峰时段的波动会比白天更明显。

    E5-2697 v4 是一颗 2016 年发布的服务器处理器，单核 Sysbench 得分 751 events/s，内存吞吐 3,370 MiB/s。跑博客、反向代理或 Docker 轻量应用足够，计算密集型任务会比较吃力。

    磁盘测试采用 psync 引擎与单队列深度，4K 随机混合读写未绕过系统缓存，各约 5,090 IOPS；1M 顺序读写仅用 0.3 秒完成，也可能命中了缓存。Bench.sh 三轮写入平均 680.7 MB/s，存储表现扎实。

    带宽与下载速度 #

    带宽部分我们使用 Bench.sh 对全球多个测速节点进行了上传与下载测试：

    下载方向非常整齐，各节点都在 348 到 396 Mbps 之间，本地节点上传 412 Mbps，实测速率略高于 Sirius 套餐标注的 300Mbps。上传到远端则在 111 到 333 Mbps，苏州 194 Mbps、东京 211 Mbps。

    短板依然在亚洲方向：宁波上传仅 5.65 Mbps，香港节点上下行都不到 2 Mbps。我们用电信家庭宽带做 iperf3 测试时也观察到，未开启 BBR 时下载不到 1 Mbps，开启 BBR 后约为 10 Mbps。

    如果要用这台机器给国内用户分发文件，开启 BBR 是必需的。

    IP 属性与流媒体解锁 #

    最后我们检测了这台实例的 IP 质量与常见服务解锁情况。IP 质量部分使用 IPQuality 脚本，汇总了 Maxmind、IPinfo、Scamalytics 等多个数据库的判定：

    该 IP 在 Maxmind 中的使用地为美国洛杉矶，但注册地是波兰，因此被判定为广播 IP，IP2Location 的地区也显示为波兰。我们用 ping0.cc 补充检测，结果显示该 IP 归属 justhost.ru。

    使用类型方面，IP2Location 标记为家宽，ipregistry 的公司类型也标记为家宽，其余数据库判定为机房。风险评分整体中等：IP2Location 与 AbuseIPDB 为 0，Scamalytics 26 分，ipapi 标记为较高风险。

    邮件方面，本地 25 端口出站可用，能连通 Outlook、Yahoo、Apple、AOL、163 与新浪邮箱，但 Gmail、QQ、GMX、Mail.com 与搜狐不通。在 439 个有效黑名单数据库中，有 45 个将其标记，但没有任何一个将其正式列入黑名单。

    解锁表现非常完整。Netflix、Disney+、YouTube Premium、Amazon Prime Video、Dazn 与 TikTok 全部解锁美区，TVBAnywhere+ 与 Reddit 也可使用，只有 Spotify 无法注册。

    AI 服务同样全部可用，ChatGPT、Google Gemini 与 Claude 均能正常访问。即便以后遇到某项服务失效，JustHost 后台也可以免费更换 IP 重新尝试。

    适用场景与选购建议 #

    综合六个维度的实测，JustHost 洛杉矶的定位非常清晰：它用低廉的月付价格提供了完整的解锁能力、开放的 25 端口与免费换 IP 机制，但硬件较老，国内网络与下载速度都只是普通水平。

    适合的用户与业务：

    • 需要访问美区流媒体、ChatGPT、Gemini 与 Claude 的个人用户
    • 运行海外爬虫、社媒监控、Docker 轻量应用等需要灵活换 IP 的业务
    • 面向海外访客的网站，或需要 25 端口发送通知邮件的轻量服务

    不太适合的用户与业务：

    • 主要访客在国内、对晚高峰速度与下载速度敏感的网站
    • 对 IP 注册地有严格要求、必须使用美国注册原生 IP 的平台账号
    • 编译、转码等对 CPU 算力要求较高的计算任务
