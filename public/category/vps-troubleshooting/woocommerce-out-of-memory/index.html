    WordPress内存溢出怎么办：后台卡死排查、Swap设置与PHP调优 #

    先分清两种内存溢出 #

    WordPress 遇到的“内存溢出”其实有两种：一种是 PHP 单个进程超出了 PHP 的内存限制，服务器本身内存还很充裕；另一种是服务器整体内存耗尽，Linux 系统强行结束了占用最多的进程。两者的表现和处理办法完全不同：

    类型典型表现原因处理方向
    PHP 内存限制页面提示 Allowed memory size exhaustedPHP 单进程上限太低调高 PHP 内存限制
    系统内存耗尽数据库连接失败，网站整体打不开物理内存不够用加 Swap、调优或升级
    后台慢但不报错保存与查询都要很久单核性能或数据库慢缓存或换高主频

    第一种只需要改配置；第二种最常见的情况是 MySQL 被系统结束，网站提示“建立数据库连接时出错”，重启数据库后能恢复，但过几天又会出现。第三种严格来说不是溢出，但很多人会把它当成内存问题处理。

    用三条命令确认 #

    登录服务器后，先用下面三条命令看清楚内存的实际情况。第一条查看内存和 Swap 用量，第二条查看系统是否因内存不足结束过进程，第三条列出占用内存最多的进程：

    free -h
dmesg -T | grep -i "killed process"
ps aux --sort=-%mem | head -n 10

    如果 dmesg 里能看到 mysqld 或 php-fpm 被结束的记录，就是系统内存耗尽；如果没有任何记录、只有页面报内存耗尽，多半是 PHP 内存限制。free -h 中 Swap 一栏为 0，说明这台机器还没有配置交换分区。

    第一步：设置Swap交换分区 #

    Swap 是在硬盘上划出一块空间当作备用内存，物理内存用完时，系统会把不常用的数据挪到 Swap 里，避免直接结束进程。它比内存慢得多，不能代替升级，但能让小内存机器在访问高峰时撑过去。

    这台机器标称 1G 内存，系统识别为 913MB，开机后已用 361MB，Swap 只用了几百 KB。如果你的机器 Swap 已用量长期在几百 MB 以上，就说明物理内存经常不够用。

    没有 Swap 的机器，可以用下面的命令创建一个 2GB 的交换文件并设为开机自动挂载。1G 到 2G 内存的机器建议设置 1~2GB，硬盘空间紧张的话可以把 2G 改成 1G：

    fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

    创建完成后，再把 vm.swappiness 调低到 10 左右，让系统优先使用物理内存，只在不够时才动用 Swap。需要注意的是，OpenVZ、LXC 这类容器虚拟化的机器通常无法自行创建 Swap，KVM 架构的 VPS 都可以。

    第二步：调整PHP内存限制 #

    如果页面报错是 Allowed memory size exhausted，说明 PHP 单个进程的上限太低。WooCommerce 官方建议至少 256M，可以在网站根目录的 wp-config.php 中，/* That's all, stop editing! */ 这一行之前加入：

    define( 'WP_MEMORY_LIMIT', '256M' );
define( 'WP_MAX_MEMORY_LIMIT', '512M' );

    前一项是前台的上限，后一项是后台的上限。这两项不能超过服务器 php.ini 中的 memory_limit，改完没生效的话，需要同时调高 php.ini 里的数值，再重启 PHP-FPM。宝塔等面板可以直接在 PHP 设置页修改。

    调高 PHP 内存限制只是给单个进程更多空间，并不会增加服务器的总内存。如果服务器本身已经吃紧，把限制调得太高反而会让几个进程同时占满内存，引发更严重的系统内存耗尽。

    第三步：调优PHP-FPM与数据库 #

    小内存机器上，最常见的问题是 PHP-FPM 进程开得太多。每个 WordPress 进程通常占用 40~80MB，WooCommerce 页面可能超过 100MB，进程数一多，内存很快就会被吃光。可以按下面的思路设置：

    • pm.max_children：可用内存除以单进程占用；
    • pm 模式：小内存机器用 ondemand；
    • pm.max_requests：设为 500 左右防内存泄漏。

    比如 2G 内存的机器，扣除系统和数据库约 800MB，剩余约 1.2GB，按每个进程 80MB 计算，max_children 设为 12~15 比较稳妥。数据库方面，MySQL 的 innodb_buffer_pool_size 在 2G 机器上设为 256M~512M 即可，不要照搬大内存服务器的配置。

    第四步：缓存与插件排查 #

    减少 PHP 和数据库的工作量，是降低内存占用最有效的办法。页面缓存让访客直接读取生成好的页面，Redis 对象缓存则把频繁的数据库查询结果保存在内存里，WooCommerce 后台的响应速度会明显改善：

    • 页面缓存：WP Super Cache 等缓存插件；
    • 对象缓存：Redis 搭配 Redis Object Cache；
    • 找出重插件：用 Query Monitor 查看耗时。

    插件是内存占用的另一个大头。页面构建器、统计分析、备份插件和各种营销弹窗都可能占用大量内存，用 Query Monitor 找出耗时和内存最高的插件，停用一段时间对比效果，往往比加配置更划算。

    什么时候该升级配置 #

    调优做完之后，如果下面几种情况仍然存在，就说明当前配置确实不够用了，继续优化的收益很小，直接升级更省时间。判断时最好观察一周以上，避开偶发的流量高峰：

    • Swap 长期占用一半以上：物理内存明显不足；
    • dmesg 仍有进程被结束：调优后仍会耗尽；
    • CPU 空闲但后台仍慢：单核性能成了瓶颈。

    前两种情况要加内存，第三种则是换单核性能更强的机器。WooCommerce 起步阶段 2核4G 一般够用，不同电商程序的配置建议可以参考 外贸独立站VPS推荐。

    内存不足VPS选型建议 #

    选升级方案时，先根据排查结果判断瓶颈在哪里：系统内存耗尽、Swap 长期占满的，要选加内存方便的商家；内存够用但后台操作慢的，换高主频机器比加内存更有效。

    内存是主要瓶颈 #

    如果 dmesg 里反复出现数据库被结束的记录，加了 Swap 和调优之后依然如此，那么最直接的办法是加内存。按网站的运行方式和流量规律，可以这样选：

    • 长期运行，原地升级：搬瓦工 VPS
    • 流量波动，按需加减：Kamatera 云服务器
    • 低成本单独加内存：CloudCone SC2

    搬瓦工适合业务稳定增长、希望一台机器长期用下去的站长；Kamatera 适合有明显促销周期的商城；CloudCone 加内存最便宜，但处理器较老，适合内容站而不是订单频繁的商城。

    单核性能是主要瓶颈 #

    如果内存和 Swap 都很宽裕，CPU 也不忙，但后台保存、搜索和订单处理依然很慢，那么瓶颈多半在单核性能和磁盘读写上。这时候可以这样选：

    • 站内单核最高：GreenCloud Ryzen VPS
    • 企业云，单核也不弱：Kamatera 云服务器

    GreenCloud Ryzen 的单核得分是 Kamatera 的两倍多，价格也更低，是 WooCommerce 后台提速性价比最高的选择；Kamatera 胜在配置可随时调整。更多高主频机型的对比，可以看 VPS 真实性能测评室。

    常见问题解答 #

    WordPress 提示内存耗尽，一定要升级吗？ #

    不一定。如果报错是 Allowed memory size exhausted，通常只是 PHP 内存限制太低，在 wp-config.php 和 php.ini 里调高就能解决。只有服务器整体内存耗尽、数据库反复被结束，才需要考虑加 Swap 或升级配置。

    建立数据库连接时出错，是内存问题吗？ #

    很可能是。小内存 VPS 上，这个报错最常见的原因是 MySQL 因内存不足被系统结束。用 dmesg -T | grep -i "killed process" 查看记录，如果有 mysqld，就按本文的顺序加 Swap、调优或升级。

    Swap 设置多大合适？ #

    1G 到 2G 内存的机器，设置 1~2GB 就够了；4G 以上的机器设置 1~2GB 作为兜底即可。Swap 不是越大越好，它的速度远低于内存，如果长期大量使用 Swap，网站会变得很慢，这时候应该加内存。

    1G 内存能跑 WooCommerce 吗？ #

    能跑起来，但很勉强。1G 内存装好系统、数据库和 PHP 之后所剩不多，商品和插件一多就容易溢出。建议至少 2G 内存起步，并配置 Swap 和对象缓存，订单量上来后再升级到 4G。

    加了 Redis 缓存反而更占内存？ #

    Redis 本身会占用一部分内存，但它能大幅减少 PHP 和数据库的工作量，总体上通常是省内存的。小内存机器上可以给 Redis 设置 maxmemory 上限，比如 64MB 到 128MB，避免它无限增长。
