    Nginx Proxy Manager教程：Docker部署图形化反代、免费SSL与502报错排查 #

    一台 VPS 上放了博客、网盘和几个 Docker 服务之后，Nginx 配置文件会越写越多，每加一个域名都要复制一段 server 块，再手动申请证书。哪天证书忘了续期，网站就会直接打不开。

    Nginx Proxy Manager（下文简称 NPM）把这些操作搬到了网页界面里：填域名、填后端地址、勾选 SSL，证书自动申请并续期。这篇文章讲清它适合什么场景、怎么部署、常见报错怎么排查，最后推荐两家适合做反代入口机的低价 VPS。

    先判断要不要用NPM #

    NPM 并不是所有人都需要。只放一个网站、配置很少改动的话，手写 Nginx 配置加上 certbot 自动续期就够了。下面几种情况，换成 NPM 会明显省事：

    • 站点较多：同一台机器要放三个以上的域名；
    • 容器较多：多个 Docker 服务各占一个端口；
    • 证书常出错：续期失败或忘记续期导致网站打不开。

    NPM 本身也是一个 Docker 容器，会占用服务器的 80 与 443 端口。如果服务器上已经装了 Nginx、宝塔或其他面板，需要先停掉原来的 Web 服务，或者把 NPM 部署到一台单独的入口机上，再把请求转发给后端服务器。

    常见问题与原因对照 #

    下表整理了用 Nginx 或 NPM 做反代时最常见的几种现象。需要注意的是，很多报错并不是 NPM 本身的问题，而是后端服务、Docker 网络或域名解析没有配好，排查时最好从后往前逐项确认：

    现象常见原因处理方向
    网站显示 502后端地址或端口填错改用容器名或内网 IP
    证书申请失败域名未解析或 80 端口不通检查解析与防火墙
    NPM 无法启动80 或 443 端口被占用停掉原有 Nginx
    证书到期未续手动申请后忘记续期交给 NPM 自动续期
    访问跳转循环CDN 与 NPM 都强制 HTTPS调整 CDN 的 SSL 模式

    其中 502 最常见，原因往往是在 NPM 里把后端地址填成了 127.0.0.1。NPM 运行在容器里，它眼中的 127.0.0.1 是容器自己，而不是宿主机，所以请求转发不出去。

    Nginx Proxy Manager部署与配置 #

    下面的步骤以 Debian 或 Ubuntu 系统为例，前提是已经把要用的域名解析到这台 VPS 的 IP。整个过程只需要十几分钟，之后添加新网站都在网页界面里完成。

    安装 Docker 与 Compose #

    如果服务器还没有 Docker，可以使用官方安装脚本 curl -fsSL https://get.docker.com | sh 一键安装，新版 Docker 自带 Compose 插件。安装完成后执行 docker compose version，能看到版本号就说明可以继续。

    用 Compose 部署 NPM #

    新建一个目录，例如 /opt/npm，在里面创建 docker-compose.yml 文件。下面是官方文档给出的基础写法，三个端口分别对应 HTTP、HTTPS 与管理后台：

    services:
  app:
    image: 'jc21/nginx-proxy-manager:latest'
    restart: unless-stopped
    ports:
      - '80:80'
      - '443:443'
      - '81:81'
    volumes:
      - ./data:/data
      - ./letsencrypt:/etc/letsencrypt

    保存后在该目录执行 docker compose up -d，等待镜像拉取完成，再用浏览器访问 http://你的IP:81 进入管理后台。首次登录按页面提示设置管理员账号；旧版本使用默认账号 admin@example.com 与密码 changeme，登录后立即修改。

    添加代理主机与证书 #

    在后台的 Proxy Hosts 页面点击新增，填入域名、后端地址与端口，再切换到 SSL 选项卡选择申请 Let’s Encrypt 证书，并勾选强制 HTTPS。保存后证书会自动申请，到期前也会自动续期，不需要再写定时任务。

    后端是同一台机器上的 Docker 容器时，建议把它和 NPM 放进同一个 Docker 网络，后端地址直接填容器名，例如 nextcloud；后端是另一台服务器时，填它的公网或内网 IP。管理后台的 81 端口最好在防火墙里限制访问来源。

    常见报错排查 #

    遇到 502 时，先在宿主机执行 docker ps 确认后端容器正在运行，再检查 NPM 里填的地址和端口是否是容器内部端口。证书申请失败时，用国内外在线工具确认域名已经解析到本机，并检查云防火墙是否放行了 80 端口。

    NPM 无法启动的话，执行 ss -lntp | grep -E ':80|:443' 查看端口被谁占用，常见是系统自带的 Nginx 或 Apache，停掉并禁止开机自启即可。日志可以用 docker compose logs -f 实时查看，大部分报错原因都会直接写在里面。

    反代入口机选型建议 #

    选反代入口机，先想清楚 NPM 要和网站放在同一台机器上，还是单独做一台入口：放在一起省钱，适合个人项目；单独一台入口机更灵活，后端服务器可以随时更换，也能把多台机器统一到一个 HTTPS 网关后面。

    个人项目与长期运行 #

    如果你只是给自己的博客、网盘和几个小工具统一配置域名和证书，访问量不大，NPM 和这些服务放在同一台机器上就够了。这时候最看重的是长期成本：

    • 年付最低、1Gbps 端口：RackNerd 特价机

    RackNerd 的 1G 特价机足够跑 NPM 加两三个轻量容器；如果要同时跑网盘或数据库，建议选 2G 内存的款式。网站主要面向国内访客时，可以参考 VPS晚高峰卡顿怎么办 改选优化线路。

    流量较大与多后端 #

    如果入口机要转发图床、下载站这类流量较大的服务，或者要把多台后端服务器统一到一个入口后面，流量额度和端口带宽就比价格更重要。按使用方式，可以这样选：

    • 月付 20TB 大流量：ColoCrossing Cloud VPS

    ColoCrossing 按月付费，流量用量变化时可以随时升降配置；它的 IP 风险评分偏高，入口机只做转发影响不大，但不适合用来登录对 IP 敏感的账号。后端放在哪家都可以，入口机和后端最好在同一地区，减少一次绕路。

    常见问题解答 #

    Nginx Proxy Manager 需要多大内存？ #

    NPM 本身很轻量，1G 内存的 VPS 就能运行，还能再跑几个轻量容器。如果同一台机器上还要跑网盘、数据库这类服务，建议选 2G 以上内存，并按 WordPress内存溢出怎么办 里的方法配置 Swap。

    NPM 和宝塔面板能一起用吗？ #

    不建议装在同一台机器上，两者都要占用 80 与 443 端口，会互相冲突。已经在用宝塔的话，可以继续用宝塔管理网站；想换成 NPM，就先停掉宝塔的 Nginx，或者把 NPM 装到另一台入口机上。

    证书申请一直失败怎么办？ #

    先确认域名已经解析到这台 VPS，并且 80 端口能从外网访问，Let’s Encrypt 需要通过 80 端口验证域名。如果域名开启了 CDN 代理，可以先暂时关闭代理再申请，或者在 NPM 里改用 DNS 验证方式。

    反代入口机和后端服务器要在同一个机房吗？ #

    不是必须的，但最好在同一地区。入口机和后端之间每多一次跨洲转发，访问就会多出几十到一百多毫秒的延迟。后端在洛杉矶，入口机也选美西机房，体验会好很多。
