    VPS误删数据怎么恢复：快照回滚、备份恢复与自带快照备份的VPS #

    一条 rm -rf 敲错了目录，一次系统升级之后网站白屏，或者服务器被人入侵改得面目全非，这些都是用 VPS 迟早会遇到的事故。能不能救回来，几乎完全取决于出事之前有没有留下快照或备份，以及出事之后第一步做得对不对。

    这篇文章先讲怎么判断数据还能不能救，再讲有快照和没快照两种情况下的处理办法，最后对比六家自带快照或备份功能的商家：Evoxt、搬瓦工、DIYVM、GreenCloud、Vultr 与 CloudCone，每家都附上套餐表。

    先判断数据还能不能救 #

    快照和备份是两种东西。快照是某一时刻整台机器磁盘的状态，回滚很快，但通常和服务器放在同一套存储里；备份是把数据复制到别的地方，恢复慢一些，但母机故障时依然在。出事后先确认手里有哪一种：

    • 商家后台：查看快照列表与自动备份记录；
    • 服务器本地：查找面板或脚本生成的备份文件；
    • 服务器之外：检查对象存储、网盘或本地电脑的副本。

    三处都没有的话，就只能靠服务器上残留的数据补救，成功率会低很多。所以在动手修复之前，先把能确认的备份都找出来，再决定是整机回滚，还是只恢复其中一部分文件。

    常见事故与恢复方式对照 #

    下表整理了几种常见的事故。需要注意的是，整机回滚会把快照之后的所有改动一起撤销，包括新增的订单和文章，回滚之前先想清楚这段时间里有没有需要保留的数据：

    事故有快照或备份没有快照或备份
    误删网站文件恢复单个目录从本地或 Git 重新上传
    误删数据库恢复数据库导出文件尝试 binlog 恢复
    升级后网站白屏整机回滚到升级前查日志、回退软件版本
    服务器被入侵回滚到入侵前并改密码备份数据后重装系统
    母机硬件故障只有异地备份能恢复等商家修复，可能丢数据

    前四种事故只要手里有一份较新的快照，几十分钟内就能恢复。最后一种比较特殊：快照通常和服务器存放在同一套存储里，母机彻底损坏时快照可能一起丢失，这时候只有存放在其他地方的备份才可靠。

    误删数据的处理办法 #

    无论有没有快照，下面的第一步都一样：先停止往磁盘写入，再动手恢复。其余几步按手里有什么备份来选，平时的备份习惯放在最后，事故处理完之后最好把它补上。

    先停止写入，别急着重装 #

    误删文件后，被删除的数据在磁盘上往往还在，只是空间被标记为可覆盖。继续写入会把它们彻底覆盖掉，所以第一时间停掉网站和数据库服务，更不要急着重装系统，重装会把磁盘上所有残留数据全部清空。

    有快照：整机回滚 #

    在商家后台选择出事前的快照，执行恢复即可，整台机器会回到拍快照那一刻的状态。回滚前建议先给当前状态再拍一个快照，万一回滚后发现丢了新数据，还能从这个快照里把需要的文件找回来。

    有备份：恢复单个文件 #

    只误删了一个目录或一张表时，没必要整机回滚。可以用备份新建一台临时机器，或者把备份文件下载回来，只取出需要的文件和数据库导出，再上传到原服务器，其余数据保持不动。

    没有快照：尽力补救 #

    数据库开启了 binlog 的话，可以用 mysqlbinlog 把误删前的操作重放回来；网站文件则可以从本地开发环境、Git 仓库或 CDN 缓存里找回。这些办法都不能保证完整，补救完成后，第一件事就是把定期备份建立起来。

    事后：建立定期备份 #

    比较稳妥的做法是三层备份：改动前手动拍快照，商家的自动备份作为日常兜底，再用 cron 定时导出数据库，配合 rclone 同步到对象存储或网盘。这样不论是误操作还是母机故障，至少有一份数据在服务器之外。

    快照备份选型建议 #

    选择快照与备份功能，先想清楚你更怕哪一种事故：怕自己误操作，手动快照就够了；怕母机故障、整台机器连同快照一起丢失，就需要异地备份。两类需求对应的商家不同。

    如果网站要长期运行、数据积累多年，最需要防的是母机故障这类自己无法控制的事故。这时候优先选择备份存放在异地的商家，再加上自己的定期导出：

    常见问题解答 #

    快照和备份有什么区别？ #

    快照记录的是整台机器某一时刻的磁盘状态，回滚很快，但通常和服务器存放在同一套存储里。备份是把数据复制到别的地方保存，恢复慢一些，但服务器或母机故障时依然可用。两者最好同时使用。

    回滚快照会丢数据吗？ #

    会丢失快照之后产生的所有改动，包括新发布的文章、新的订单和用户注册。回滚前建议先给当前状态拍一个快照，回滚后如果发现缺了数据，可以再从这个快照里把需要的文件找回来。

    误删文件后能用数据恢复工具找回吗？ #

    有一定机会，但成功率不高。VPS 通常使用虚拟磁盘和 SSD，删除后的数据很快会被覆盖或回收。第一时间停止写入，再尝试 extundelete 等工具；如果数据很重要，与其冒险，不如直接从快照或备份恢复。

    多久备份一次比较合适？ #

    取决于数据变化的频率。个人博客每周备份一次就够了；有订单、评论或用户数据的网站，数据库建议每天导出一次；大的升级和改动之前，再手动拍一个快照，这样最多只会丢失一天的数据。

    商家自带的备份够用吗？ #

    作为兜底够用，但不建议只依赖它。商家备份的频率和保存份数有限，账户出问题或服务器到期时备份也可能一起删除。重要数据最好再保存一份在服务器之外，例如对象存储或本地电脑。
